## 1. 产品业务流程（端到端）

### 1.1 日常主线（留存引擎）

```
        你
         │  带一篇新原文 / 从素材池挑一篇 / 接着上次
         ▼
   ┌─ Practice：就着原文 读 + 对抗式 drill ─┐
   │   [拆训练点 = 当场展示，引导本次，不留痕] │
   └──────┬──────────────────────┬──────────┘
     过线 → 不留痕            答崩 → 复习项进账本(持久)
          │                        │
   会话中断→「继续上次」(临时续播)    ▼
                              失败账本(唯一从内容长出的持久状态)
                                   │ 调度器按 next_due
                                   ▼
                          首页「今日复习」块 ──把你拉回来──┐
                                                          │
         └────────────────── 你回来再练 ◀─────────────────┘
```

**主动学习负责拉你回来 + 制造失败；失败账本负责接住 + 再拉你回来。** 文档不被建模，只有"你答崩的点"沉淀。

### 1.2 面试战役（钩子 · 同一回路 + 三层薄叠加）

```
立项(deadline+JD) → 范围(JD拆扁平起步话题+覆盖度清单) → 每天冲刺(deadline感知调度)
   → [可选]模拟连播(就绪度读数) → 面试当天(你自己的薄弱点清单)
   → 面试后回灌(真实失败→复习项) → 收尾(归档Goal、丢覆盖清单)
                                          │
                                复习项留下 → 流回日常主线 (留存桥)
```

叠加层只有：① deadline 调度 ② per-Goal 覆盖度清单 ③ 压力参数。**不是新引擎。** 有自己的仪表盘页，但纯视图、零自有状态（PRODUCT.md §1.3 安全测试）。

## 2. Practice 内部：结构保留，改的是底层记忆形状

现 `/learn` 的"弱阅读 helper + 强单页练习流程"结构**保留不动**（阅读 helper 已是 §1.4 贬值区的薄设计、练习已是单页强流程）。读 + drill 的交互**基本原样**。真正改的只有底层：

- **判分输出**：从"掌握度 %（带动画）"→ **锚点命中/漏**，漏的写进**全局失败账本**（§0.1 / §4）。掌握度改为复习项的**派生视图**（shaky/solid 聚合），不再每概念存分。
- **记忆形状**：从 `capability-memory.js` 的 **concept-keyed 掌握度打分图**（概念本体 + 每概念存分，踩 §1.6 / §4 红线）→ **失败为单元的扁平账本**（只在答崩时生）。这是 §6 那行"capability-memory → 复习项账本"的实质。
- **输入**：**一次性提交（提交即定稿，常开）**；**可见倒计时仅面试模式**，日常不施压（§0.2）。

> 阅读 helper 是"你问它"= §1.4 贬值区，**够用就行**；drill 是"它问你"= 脊柱、价值与账本所在。两者权重差很大，但**不需要改现有结构**——现状已经如此。

## 4. 当前页面 → 目标改动映射

| 现页面 | 目标形态 | 复用 | 主要改动 | 风险 |
|---|---|---|---|---|
| `/` home-page (1759) 文档库 | **act-led 首页** | 低–中 | 在读/已掌握/未学分组拆掉 → 继续/今日复习/学点新的；文档库降素材池 | ⚠️ 改最狠 |
| `/learn` learn-workspace (4634) 阅读+drill | **Practice 主动学习入口** | **很高** | 页面/双栏/阅读 helper/练习流程**全保留**；只改底层 3 处：① 掌握度 % → 锚点命中/漏 + shaky/solid 派生视图；② 判分结果写**全局失败账本**（替掉 concept-keyed `capability-memory`）；③ 输入改一次性提交（日常无倒计时） | 低–中 |
| `/loopassist` (2373) 对抗追问 | **Practice 复习/面试档** | 高 | 溶进同一 Practice 题型；面试=参数；TTS 已拔 | 低 |
| `/materials` 导入 | Setup 导入 + 素材池 | 高 | 基本沿用，多"Goal 类型/deadline/JD"一问 | 低 |
| `/profile` 档案 | 档案（次要页） | 高 | 基本不动 | 低 |
| `/documents/[slug]` 阅读器 | Practice 双栏左侧 | 高 | 当阅读窗复用 | 低 |

**跨页两处共性改动**：① §0.2 输入 → 一次性提交（日常无倒计时，倒计时仅面试）；② §0.1 判分 → 锚点命中/漏 + 漏的写账本。

**结论**：真正伤筋动骨只有 `/` 首页一处；最大投入 `/learn` 是**保留最多**的。

## 5. 实施顺序（去风险优先）

0. **阶段 2（零依赖可跑 · 已完成）**：TTS 从 `ai-service/app/main.py` 摘除（worker 独立保留）；`start-services.sh` 加 `ENABLE_TTS`（默认关）守护 TTS worker 启动 / 健康检查 / pid / 摘要。`npm start` 不装 TTS 也能跑通核心 loop。
1. **阶段 3（脊柱 · 已完成 ✅）**：失败账本写入路径全线打通。
   - `src/ledger/review-item-store.js`（§4 五字段，JSON 存 `.omx/review-ledger/`）
   - `ai-service/app/engine/anchor_judge.py` + `/api/anchor-judge`（一次性锚点判分，防判太松）
   - `src/ledger/{anchor-judge,drill-passthrough,extract-drill-round}.js`（Node 适配器 + 穿透适配器 + turns 抽取）
   - 接线（C，两条 drill 回路）：BFF `handleAnswer`（/learn，awaited+兜底）& `/api/loopassist/review`（detached 逐题）。
   - 测试：19 Node + 7 Python，全绿。
   - **唯一暂留中间态**：`capability-memory` 的写还在（首页/档案仍读它）——是首页重构时一关的开关，非脚手架。
   - **判分复用现有 engine 的 LLM 管线，不是 `mastery_scoring.py`**（那是确定性打分聚合器，无 LLM）。一次性锚点判分 = `ai-service/app/engine/anchor_judge.py`，复用 `stream_provider_text_chunks`（tutor_intelligence）+ `parse_provider_json_text`（domain/interview/parsers）+ loopassist 已有的 `misses` 判分模式 + mock-for-test，**不碰 concept-anchor 本体**（context_packet 里的 `anchorIdentity` 是要弃用的概念图，与 §0.1 的一次性锚点同名但相反）。`src/ledger/anchor-judge.js` 只是调 ai-service endpoint 的薄适配器。
2. **阶段 4（UI 转向，账本读出口 · 进行中）**：act-led 首页 + Practice 合并（learn+loopassist）+ 面试仪表盘页。
   - ✅ **最小读出口已落**：BFF `GET /api/review/today`（读 `reviewItemStore.listDue`，读写共用一个 store 实例）+ 首页顶部「今日复习」块（读真实账本、mockup 样式、有限改动，不动现有文档库）。Next build 通过；写/读两端真实 HTTP 冒烟均过。
   - ✅ **真调度器已落**：`src/ledger/review-scheduling.js`——shaky 隔天、solid 按连续次数 streak 阶梯扩张 `3/7/16/35/75` 天、deadline 封顶；刻意不套 SM-2/FSRS（§4）。7 测试。
