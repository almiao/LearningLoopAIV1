# 架构与业务流程

> 这是"一眼看懂这个系统"的门面。产品取舍的单一事实源是 [PRODUCT.md](../PRODUCT.md);
> 本文负责把它翻成一张流程图 + 一套术语。

---

## 一句话

把你的资料/JD/笔记,练成你真能讲出来的东西。系统只记一件事——**你答崩的点**——
然后按遗忘节奏把它推回你面前,直到你讲得稳。

---

## 业务流程闭环

渲染版见 [architecture-flow.svg](architecture-flow.svg)。文本版:

```
      今日复习            学新东西            面试冲刺
    (账本到期项)        (带一篇原文)       (JD 话题+倒计时)
        │                  │                  │
        └────────┬─────────┴──────────┬───────┘
                 ▼                            （三入口,同一引擎）
        ┌──────────────────────────────────────────┐
        │              操练引擎 (LLM)                │
        │                                            │
        │   出题 ──▶ 你作答 ──▶ 锚点判分             │
        │  (针对漏的    (一次性     (命中/漏          │
        │   锚点变体)    提交)      哪几个)           │
        │                  ┌──────────┴──────────┐   │
        │              过线│                  答崩│   │
        │                  ▼                     ▼   │
        │              转扎实               补讲     │
        │           (会了就放走)         (靶向讲解)  │
        └──────────────────┬─────────────────┬───────┘
                           ▼                 ▼
                  ┌─────────────────────────────────┐
                  │          失败账本 (确定性)        │
                  │   你答崩的点 · 扁平一列 · 持久    │
                  │                                  │
                  │   新建 ──答崩──▶ 生疏 ⇄ 扎实      │
                  │               过线↗  ↘又崩       │
                  └────────────────┬─────────────────┘
                                   ▼
                              调度器
                          (按下次到期拉队列)
                                   │
                          次日 ──▶ 今日复习  (回到顶部,闭环)
```

**两层颜色就是整个架构**:
- **LLM 层**(出题/判分/补讲)= 当场生成、用完即弃,什么都不记。
- **确定性层**(失败账本/调度)= 唯一持久记忆,持有"你到底会不会"的真相。

LLM 负责生成,确定性系统负责状态——这是护城河:跨时间的记忆是单次 LLM 调用结构性补不上的洞。

## 术语表(中文为准)

| 词 | 含义 |
|---|---|
| **练习** | 产品本体,你每天来做的事。一次练习 = 3-5 轮操练 |
| **操练**(practice) | 一轮针对性练习 |
| **出题** | LLM 当场生成一道题。复习时针对"漏的锚点"出变体,不重放原题 |
| **锚点** | 过这道题"必须命中的点",判完即弃、不入库、不复用 |
| **锚点判分** | 判"那几个锚点你说了没",输出命中/漏,而非裸分数 |
| **补讲** | 答崩后,针对漏的点生成的靶向讲解(test-first 的失败承接) |
| **复习项** | 失败账本里的一条 = 你答崩的一个点。唯一从内容侧长出的持久单元 |
| **失败账本** | 唯一的持久记忆。扁平一列复习项,无图、无边、无本体 |
| **失败证据** | 崩的那道题 + 没命中的锚点,冻进复习项 |
| **原文指针** | 指回原文那段,供回看。原文被检索,不被建模 |
| **生疏 / 扎实** | 复习项两档状态(shaky / solid) |
| **下次到期** | 这条复习项下次该出现的时间 |
| **今日队列** | 首页"今日复习",账本按下次到期渲染 |
| **目标**(Goal) | 日常目标 或 面试冲刺。唯二持久实体之一(另一个是复习项) |
| **标题句** | 一句话说清这条复习项练什么 |

## 记忆/信息的三种去向

| 信息 | 性质 | 去向 |
|---|---|---|
| **原文** | 被检索,不被建模 | 出题时当上下文,用完不留。是源,不是记忆 |
| **近期对话** | 临时连续性 | 只在这一轮操练内有效,可随时丢。不是记录 |
| **失败证据** | 唯一被冻存的残渣 | 判分一出"漏了哪几个",冻进复习项 |
| **复习项** | 唯一持久记忆 | 既是结果(答崩写入),又是种子(下次出题靠它) |

一句话:**LLM 层什么都不记,账本层只记唯一该记的——你答崩的点。**

---

## 复习项状态机

- **答崩** → 新建一条,落 `生疏`,下次到期 = 短间隔
- 复习时 **过线** → `生疏 → 扎实`,间隔拉长(放你走,不浪费时间)
- 复习时 **又崩** → `扎实 → 生疏`,间隔缩短,**触发补讲**
- **一次过的不留痕** —— 账本只长失败,不给"碰过的一切"建模

## 为什么这条流程立得住(实测,非口号)

1. **有意义**:test-first(提取练习)是学习科学最硬的结论之一;跨时间的失败记忆是 LLM 补不上的洞。
2. **AI 干得好**:出题/追问是 LLM 强项;最担心的锚点判分,24-case 校准 eval 跑下来 `false_pass=0%`(空话/背定义/虚构事实/堆名词全判挂)。见 `ai-service/evals/`,跑 `npm run eval:judge`。
3. **是核心**:资源 60% 在操练引擎、25% 在账本/调度(PRODUCT.md §5)。

## 单引擎护栏(成败判据)

三个入口、面试冲刺,**永远只是同一个操练引擎的参数化**。绝不允许长出独立引擎或独立状态库。
面试冲刺可以有自己的仪表盘页,但那是对共享引擎 + 共享账本的纯视图,零自有状态。
判据永远是"有没有独立引擎/状态",不是"有没有独立页面"。(PRODUCT.md §1.3)
